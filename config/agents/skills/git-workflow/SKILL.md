# Git 工作流

项目 `AGENTS.md` 和项目增量 Skill 优先于本通用基线。

## 提交准备

1. 查看 `git status`，识别用户已有修改和未跟踪文件。
2. 查看 `git diff --stat`、`git diff --name-status` 和关键详细 diff。
3. 按主题分组；每个 Commit 只包含一类改动。
4. 项目要求确认分组时，先展示分组方案。
5. 执行项目质量门禁，禁止 `--no-verify`。
6. 提交后复核状态和提交记录。
7. 仅在用户明确要求时 push。

## Commit 规范

- 使用 Conventional Commits。
- 首行简洁说明业务变化。
- 必须包含有效正文，清楚覆盖问题现象、分析原因、修改内容和修改后结果。
- 形式和顺序不限，不要求固定标签。
- 不得只罗列文件、使用占位符或声称未执行的验证。

## 分支与合并

- 功能分支使用 `<类型前缀>/<简短描述>`。
- 子分支默认 Squash merge 到主分支或版本干线。
- Squash 汇总正文必须保留有效行为变化、工程影响和验证结果。
- 合并后更新路线图、专项状态、当前架构、接口、运维和变更日志；不得通过移动专项目录表达完成状态。
- 只有失效、被替代或取消的资料进入归档区。

## 安全边界

- 未经明确要求不 push。
- 未经明确授权不改写已推送历史。
- 禁止向共享分支 force push。
- 删除本地或远程分支前确认目标和授权。
- 不使用 `git add -A` 混入未审查的无关改动。
