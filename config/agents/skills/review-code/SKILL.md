# 代码审查工作流

项目 `AGENTS.md` 和项目增量 Skill 优先于本通用基线。

## 原则

- 审查阶段只报告问题，不擅自修改。
- 以实际代码路径、运行行为和契约为证据。
- 大范围变更按独立模块拆分；是否并行由项目规则和用户指令决定。
- 修复后必须复查，并执行项目质量门禁。

## 范围

| 模块     | 检查重点                             |
| -------- | ------------------------------------ |
| 接口     | 参数、响应、鉴权、状态和错误契约     |
| 业务     | 逻辑、状态流转、异常和事务边界       |
| 数据     | SQL、迁移、索引、约束和一致性        |
| 配置脚本 | 默认值、环境变量、路径和失败行为     |
| 模型算法 | 输入输出、边界、性能和资源生命周期   |
| 文档     | 路线图、专项、架构、接口和实现一致性 |

## 输出

```text
| 严重度 | 文件 | 行号 | 问题描述 | 建议修复 |
```

- 高：运行错误、数据不一致、安全漏洞或对外契约错误。
- 中：逻辑隐患、架构违规或遗漏边界。
- 低：可读性、命名和低风险维护问题。

汇总时去重并按严重度排序。用户授权修复后逐项处理，完成验证后重新审查。
