# 变更日志工作流

项目 `AGENTS.md` 和既有 CHANGELOG 结构优先于本通用基线。Git 历史是已提交变更的事实来源。

## 流程

1. 检查项目规则、现有 CHANGELOG、版本文件和最近 Tag。
2. 明确记录范围；用户指定分支、版本或日期时按指定范围。
3. 读取 Commit subject 和必要正文，识别实际业务变化。
4. 按项目既有的日期制或版本制结构追加内容。
5. 运行项目 Markdown 格式化和检查。

## 规则

- 不记录未提交内容。
- 不逐字机械复制每个 Commit；合并同一目标的过程变更。
- 保留功能、修复、性能、重构、文档和工程影响。
- 不把纯 Merge Commit 当作独立功能；Squash 汇总 Commit 按实际内容记录。
- 不静默改写既有历史；发现错误时先说明。
- 详细日志关注行为、配置、迁移和兼容影响，不堆砌文件路径。
