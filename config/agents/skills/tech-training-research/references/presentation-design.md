# 个人技术演讲设计规范

适用于以简体中文为主、支持中英文混排的技术培训、团队分享、算法研究与架构讲解，覆盖 HTML 幻灯片及可编辑 PPTX。用户当前指定的品牌、背景、字体和交付要求优先。

## 1. 设计定位

采用现代编辑设计（Editorial Design）、瑞士国际主义排版（Swiss International Style）与分析型信息设计（Analytical Information Design）的思路：精确排版建立秩序，信息设计表达知识，编辑设计赋予作品个性。

设计是一套原则与方法，不是固定模板。可以借鉴出版物、海报、艺术和工业设计，但每个视觉选择都应服务于理解或构图，不能妨碍技术准确性。专业、清晰、美观、可编辑和易维护需要同时实现。

## 2. 先确定讲述，再设计画面

### 内容阶段

1. 明确听众、已有知识、演讲目标与希望记住的判断；时长按当前任务约束，不继承某次分享的时间限制。
2. 阅读研究笔记、已确认大纲与最新材料，建立「章节主题 → 小主题 → 页面」三层结构。章节之间体现因果、递进或明确的问题转换，不机械套用统一叙事。
3. 为每页确定：要回答的问题、核心结论、需要展示的具体内容、内容间关系、与前后页的承接。讲述需要的依据和中间步骤应在画面中找到对应，不能只有口头解释才能成立。
4. 内容块不等于幻灯片页数。一页围绕一个主问题；讲不透时拆为连续页面，避免将多个独立主题塞进同页，也不为凑页数把完整过程拆碎。
5. 去除重复定义、重复结论和为了完整而添加的章节。必要回顾应服务于后续推导，使用已经形成的结果，不从头再讲。
6. 已确认的大纲独立落档，供手动调整与追溯；大纲只写大纲，不夹带给制作者的解释、执行日志和审批对话。

### 设计阶段

按「内容结构 → 信息层级 → 空间布局 → 字体排版 → 图形表达 → 色彩修饰」推进。逐页判断观众先看什么、再看什么、怎样识别关系。

- 统一字体、色彩语义、对齐秩序和图形语言；不要求所有页面外观一致。
- 概念突出定义、范围与边界；原理突出因果与中间变化；流程突出方向、条件和分支；架构突出层级、模块及数据流；对比使用统一维度；数据突出有依据的发现。这些是判断线索，不是固定布局映射。
- 允许非对称、多栏、跨栏、自由构图与不同信息密度；不能把所有内容都做成左右两栏、表格或同样的卡片网格。
- 用户要求「重新设计」时，重新判断信息顺序和构图，必要时拆合页面；保留内容事实和用户改动，不以替换配色、字号或容器代替重新设计。

## 3. 配色、字体与空间

### 色彩

个人视觉基准如下，角色优先于色值。允许按当前主题调整，但整套演示应保持一致的色彩逻辑。

| 角色 | 参考颜色 | HEX |
| --- | --- | --- |
| 基础背景 | 纸白 / 纯白 | `#F7F6F2` / `#FFFFFF` |
| 主要文字 | 墨黑 | `#222725` |
| 辅助文字 | 中灰 | `#666C68` |
| 分割线 | 浅灰 | `#D8DAD5` |
| 识别与强调 | 深青绿 | `#0F665D` |
| 特殊强调 | 陶土橘 | `#B66C4C` |

- 默认整套采用同一基础背景，封面、正文、章节页与尾页协调；不自动将章节变绿底、概念变黑底来制造节奏。用户明确需要不同背景时，再统一规划用途和对比度。
- 优先用字号、字重、明暗、比例、对齐和留白建立层级，颜色辅助；相同语义保持一致，关键差异同时用标签、位置或符号表达。
- 强调色不必每页出现，不滥用渐变、霓虹、发光和科技纹样。

### 字体

- 基础字体保证可读性：中文可用思源黑体、微软雅黑；英文可用 Inter、Aptos，并考虑本机可用字体。
- 表现字体用于封面、章节、短观点或引用，可选择衬线、海报、美术或其他合适字形，不固定某款字体。避免无理由混用及难读的长篇艺术字。
- 代码、终端和字符对齐内容使用 JetBrains Mono 等等宽字体；编号和标识注意 `O/0`、`I/l/1` 的区分。
- 检查字体授权、嵌入及跨设备替代；中英文混排关注比例、基线与字重。

16:9 演示的参考字号：封面 36–52 pt，章节 32–48 pt，内容标题 26–32 pt，正文 18–24 pt，辅助说明 15–19 pt，代码与公式标注 14–19 pt，页码 10–14 pt。按内容和观看距离调整，不作为硬阈值；HTML 的 CSS px 与 PPT pt 不能直接混用，应检查实际投影尺寸。

- 信息拥挤时先重组、拆页或分步呈现，不靠不断缩小文字解决。
- SVG 或嵌套图形要检查最终缩放后的文字尺寸；不能只检查源代码中的字号。
- 中文自然断句，避免单字孤行；代码不破坏缩进、语法和标识。

### 空间与容器

- 默认 16:9，可参考 12 栏网格；按实际关系决定布局，不将内容数量机械映射为模板。
- 留白用于聚焦、分组和阅读节奏，不把必要说明删掉以追求极简，也不让大量空白与拥挤的小图同时存在。
- 空间、对齐、明暗与分割线可以组织文字；背景、线框和色块适用于需要独立边界的对象、状态、代码区或模块。不要全用色块，也不要因避免卡片化而取消必要边界。
- 不用没有表达意义的横线、阴影、图标或插画填充页面。观点页、技术页、架构页可有不同密度和重心，变化应有内容依据。

## 4. 页面组织与固定区域

- 封面包含主题、必要副标题和分享人；默认不加日期、制作状态或「预览」字样。使用与主题有关的视觉结构，避免只剩普通标题，也不强制添加底图或图标。
- 正文左上为章节导航与页面标题，右上为本场主题，左下仅放公开参考资料或简短标注，右下为页码。页码两侧不放翻页按钮。
- 左下资料按文字宽度自然排列并允许换行；不把正文结论放在该区域，不把本地文件路径当公开参考资料。
- 章节之间可使用过渡页，收束上章并提出下章问题；不在每个小节之间加过渡。过渡页延续背景体系，不显示「过渡页」「某块收束」等制作标签，不默认放资料标注。
- 结尾先完成观点或业务案例的收束，再有明确致谢与交流；避免最后一页像尚未讲完的正文。
- 正文只面对观众，不保留「按你的要求」「上一页已经讲过」「下一页再拆」等向制作者解释的过程话。必要承接应直接表达知识关系，不依赖硬编码页码。

## 5. 技术内容的关系表达

### 顺序与具体例子

- 默认沿「输入 → 处理与关键变化 → 输出 → 如何使用」说明；可以沿一个稳定案例逐步展开，不先摆结果再要求观众自行反推输入。
- 新术语在首次参与过程时解释用途，不堆名词，不跳过支撑结论的中间步骤。
- 输入、规则、计算结果和业务动作采用明确标签；具体数值、单位、示例请求与响应相互一致。说明数据、政策或数值是示例时，不冒充真实评测或产品标准。
- 公式不是技术深度的唯一表达。默认优先使用具体数值、简短代码和可追踪步骤，不主动堆公式推导；用户需要公式时保留准确符号、条件、单位及必要解释。

### 图、代码与对比

- 模块、依赖、层级、分支、汇合及状态变化用图；实现细节、索引取值、后处理或计算逻辑可用简短代码。不要为了画图把简单代码扩成难懂流程。
- 关系图与流程图要明确图例或箭头含义：业务关联、查询路径、时间顺序、请求返回不混用。同一页若存在多类连线，标明差异。
- 主题要求「从某对象出发查询」时，把起点放在阅读起始位置，并展示查询后得到什么。多源信息汇合时，不只从中间一条记录画箭头而忽略其他来源。
- 权限、动作和条件要逐项对应；多个角色与一组总条件简单并排，不能替代对应关系。
- 调用过程区分请求、响应、异步后续与外部结果；状态图的重试、超时和查询不能画成不存在的新业务操作。
- 架构拆解应能对应整体图中的具体模块。分段讲解结束时，如观众仍难拼出整体，可用一页汇总已有对象与关系，不重新展开定义。
- 对比使用共同目录或维度，不能各说各话。可组合技术不能只用对等卡片暗示互斥选择；需要呈现各自职责及组合方式。
- 图表保留数据、坐标、单位、来源和真实比例，不制造不存在的优势、关系或结论；营销指标需保留评测前提。
- 请求代码按实际协议示意，不为对齐画面虚构字段。展示重点字段，其余内容可简化但须标明范围，或用可展开的完整示例补充；展开状态同样需要验证。

## 6. 图形、动画与交互

- 图标、符号、连线和图片承担语义、阅读引导或构图作用，不为每个知识点配装饰图。
- 优先相关真实素材、准确技术示意图及原生图形，不默认生成机器人、大脑、发光电路等 AI 插画填充页面。保留清晰度、来源和使用授权信息。
- 页面进入时默认完整显示内容，不自动添加逐段淡入或渐进式加载。
- 动画仅用于需要展示的变化、计算或流转，避免旋转、弹跳、闪烁和复杂转场；必要时用连续页面替代复杂动画。
- 不把动画时间点与口播硬绑定；过程可独立播放或重播，结束后保留完整结果。复杂动画看不懂时应重做表达，不以增加解释文字弥补。
- 交互必须与知识点有关，如切换输入并观察结果；初始值、标签、计算和输出同步变化。切换条件属于另一示例时，应避免被误认为修改了同一业务事实。
- 保留键盘翻页与必要的演示操作；不因减少页面按钮而移除可用导航。考虑减少动态效果的设备设置和静态导出效果。

## 7. HTML 与 PPTX 的工程约定

- 内容层（事实、标题、逻辑、代码、数据、来源）与设计层（构图、字体、颜色、间距、动画）分离；可以使用共享样式，但不能把所有内容锁进同一版式。
- 默认顺序为：内容大纲 → 每页内容确认 → HTML 设计与验证 → 可编辑 PPTX。HTML 未验证前，不同时改 PPTX，避免两边重复返工；用户另有顺序时按其要求。
- 用户改过 PPTX 后，若要求反向同步 HTML，以该 PPTX 的最新内容和排版为依据。先读取当前文件，不用旧脚本重建覆盖用户改动。
- PPTX 优先原生文本框、形状、连接符、表格、图表及公式；复杂素材可用 SVG。不得默认将整页截图作为可编辑交付。
- 连线使用原生连接符，不用若干细长形状拼接。相关对象合理分组，避免无必要碎片化。
- 普通文本框默认垂直居中、左对齐；按内容语义需要调整时说明实际效果。资料文本框开启自动换行。
- 颜色、字体和公共样式集中管理；图表尽量保留数据。考虑 Windows、macOS、WPS 及 PowerPoint 版本兼容性，不声称未验证的客户端效果。
- 先保留可恢复副本，按范围修改；临时构建脚本与预览放在临时目录，正式目录不堆重复版本和解释性 README。
- 优先文件解析、原生对象编辑和无头渲染；能否生成文件不能替代视觉检查，不自动启动已知不兼容的演示客户端。

## 8. 渲染、审查与交付

按实际风险验证；整套重构应逐页渲染并查看总览及关键页大图，小范围修改检查受影响页面与相邻承接。

### 内容审查

- 整体顺序是否连贯，每章是否回答它承接的问题？每页能否讲明当页主题，哪些内容需要拆页或合并？
- 画面是否呈现讲述所需的输入、依据、中间过程与输出？有无需要观众自己拼接或反推的断点？
- 定义、单位、数值、接口与代码是否一致？已知、推断、示例及评测前提是否清楚？
- 有无重复讲解、为讲而讲的章节、偏离主旨的工程扩展，或残留给制作者的解释？

### 视觉与运行审查

- 标题、正文和辅助信息是否有主次？阅读顺序能否自然对应实际关系？版式是否机械重复？
- 背景与色彩语义是否统一，字号和对比度是否适合实际观看？不以源字体大小代替缩放后的可读性判断。
- 检查文字溢出、截断、孤行、字体替代、图形重叠、对齐、间距、图中文字和容器边界。
- 检查连接是否贴合目标、方向是否准确、分支与汇合是否清楚；HTML 多图使用独立 SVG 标识，避免隐藏页面的重复 ID 影响当前图形。
- 检查动画最终状态、切换后的数值一致性、键盘翻页及展开内容；默认状态、完整展开状态和静态预览都应可读。
- 验证可编辑对象与目标客户端兼容性；无法实际渲染或验证时明确说明，不能将静态检查描述为完整视觉验收。

发现问题后修改并复查。分别报告内容逻辑、视觉效果和运行验证的结果；「已生成」「无溢出」「配色统一」不能单独作为设计完成的结论。
