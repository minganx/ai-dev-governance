# 技术培训 · 研究笔记工作流

先产出**研究笔记**与**专题大纲**；培训讲义、幻灯提纲由其再整理提炼，不以培训大纲作为主产出。

与 `docs-workflow`、`obsidian-notes` 同时适用时：本 Skill 管培训专题的叙事与体例；落档 Obsidian 时再遵循 `obsidian-notes`。

## 何时启用

- 准备或续写某一技术主题的培训/调研（模型、框架、架构、方法论等）
- 用户要求「研究笔记」「落档知识库」「先大纲再逐章」
- 用户强调概念要给非技术读者、要文档链接、要因果叙事

## 阶段划分

| 阶段 | 做什么 | 不做什么 |
|------|--------|----------|
| **一阶段** | 讲透概念、原理、方案、对比、训练方法思路、架构推断 | 不强求当堂跑通训练或业务验证 |
| **二阶段** | 按一阶段已写清的方案做实操、对照实验、调参 | 不把原理/方案整包挪到二阶段导致一阶段变浅 |

「时间紧、无法验证」只减轻**动手验证**，不减轻一阶段理论与方案深度。

## 叙事原则

前后要有因果关系与层次，避免散点罗列。推荐主线（可按主题裁剪，勿机械填空）：

1. **引子**：有趣或公知的现象（为何现在要讲）
2. **是什么**：对象、能力、公开事实（价目、成本示例等能贴能力的就贴在本节，不另开成本专章）
3. **为何出现**：问题背景与动机
4. **原理/底层**：可核对的机制；区分已知与推断
5. **评估与局限**：官方/第三方怎么评、弱在哪
6. **能不能用 / 复现**：边界、开源替代、自研路径
7. **同类与差异**：产品或方案对照
8. **如何应用**：结合实际场景的选型与接入建议
9. **收束**：未决问题与下一章/二阶段地图（可很短，勿再单开「本章判断」专章）

## 写作体例

### 研究笔记主语

- 标题与结构按研究专题组织，不写成「第 N 课学习目标 / 课后作业」式培训大纲。
- 培训用途的提炼（口播要点、幻灯目录）另出，或明确标注为派生材料。

### 概念与名词

- 正文首次出现的概念、名词须有**白话解释**，使非技术领域读者能跟上。
- **名词表放文档末尾作附录**，不放在开篇占主阅读路径；文首可用一句话链到附录。
- 附录与正文释义保持一致；附录可稍完整，正文保持阅读流畅。

### 引用与资料（贯穿各节）

- **不单列**「本章判断」「已知未知汇总」之类专章；判断写进正文，不另起标签段。
- **不要**每节机械堆「**依据** / **判断方式**」小标题。有资料时用简洁列表，例如：
  - `- **文档**：…`
  - `- **社区资料**：…`
  - `- **论文**：…`
- 正文先把事实或结论写清楚；链接跟在段落后，而不是用「依据（产品侧）」这类元叙述打断阅读。
- 需要提醒读者如何甄别时，用一两句正文说完（如「先分清隐喻、代号还是可下单 API」），不要单独开「判断方式」块。
- 价格、限额、延迟等易变项注明核对日期，并写「以官网实时页为准」。

### 书摘与引文

- 书籍只摘**定义或必要原句**，注明书名与章节；过长情节、例子列表默认不整段粘贴。
- 外文定义同时给**中文对照译**；正式出版译名可注明「以国内译本为准」。
- 直接引用用引用块；翻译与评论分开，避免把译注写进引用块当原文。

### 公式

- 行内公式用 `$...$`，例如单次费用约为 `$400 \times 0.042 / 10^{6}$`。
- 独立成行的公式用 `$$...$$`。
- 不用 `\[...\]` / `\(...\)` 作为笔记默认格式（Obsidian 以 `$` / `$$` 为准）。

### 成本写法

- **不单开成本专章**；价目与成本示例归入「能力 / 产品边界」或相关叙述处。
- 有官价则给**价目依据**；需要直觉时给 **「成本示例」**（调用量 × token × 单价 → 日/月；可与对照方案并排）。
- 禁止使用「说人话」作小节标题或引导语。
- 示意单价须标明假设与边界，避免写成永久官价。

### 评估与局限

- 宣传倍数、榜单、demo 须写清评测设定与 nuance。
- 官方自认弱项（若有）优先收录，并落到工程含义。

### 落档

- 用户指定知识库目录时，**大纲与各章分文件**落档；大纲维护章节状态与双向链接。
- Obsidian 路径下遵循 `obsidian-notes` 的归类与 Markdown 约定。

## 交付顺序（默认）

1. 与用户确认叙事主线与章结构（可先结构审查，再逐章正文）。
2. 写/更新 `00-研究大纲`（或等价文件）。
3. 逐章研究笔记；每章含资料索引 + 文末名词附录（或篇级附录）。
4. 用户需要时再提炼培训版（口播稿、幻灯结构），不从培训大纲倒推研究结论。

## 反模式

- 以培训大纲为主产物，研究笔记只做附录
- 开篇大段名词表打断叙事
- 单独开「成本专章」或「本章判断专章」，与各节内容重复
- 每节套「依据 / 判断方式」模板，把笔记写成检查清单
- 只贴单价表、无成本示例；或断言无链接、正文也不说明如何核对
- 大段书摘代替定义；外文无中文对照
- 公式不用 `$` / `$$`，却用难在 Obsidian 渲染的写法
- 把训练实操方案整包留到二阶段，导致一阶段过浅
- 将闭源产品内部架构写成已证实结论
- 散乱跳跃、章节之间无因果衔接
